# W009: document-once

**Level:** default

## Problem

The same fact is written in more than one place:
`README.md` and the crate-level `//!` docs,
the doc comment and the commit body that added it,
a module's documentation and every function inside it.

Copies diverge, because updating one is a complete-feeling change.
The reader who lands on the stale copy has no way to know it is the stale one —
both look equally authoritative,
and a reader who finds a contradiction has to read the code to break the tie,
which is what the documentation was supposed to prevent.

Paraphrasing an external specification is the same problem with a worse ratio:
the specification is longer, more precise, and maintained by someone else.

## Pros / Cons / Decision

**Pros of stating a fact once:**
- One place to update, so drift has nowhere to start.
- Whichever copy a reader finds is the authoritative one.
- Linking to an external specification inherits its corrections for free.

**Cons:**
- Indirection costs the reader a click, and a link can rot.
- A self-contained document is more pleasant to read than one full of pointers.

**Decision:**
State each fact once and link to it.
Include shared prose mechanically rather than by copying.
Reference external specifications rather than paraphrasing them.

## Example

### Bad
```rust
//! # mycrate
//!
//! A client for the Widget API, with retries, TLS, and connection pooling.
//! ...
//! (thirty lines pasted from README.md, which has since gained a section on
//! authentication that this copy does not have)
```

### Good
```rust
#![doc = include_str!("../README.md")]
```

And for an external specification, link rather than restate:

```rust
/// Parses an RFC 3339 timestamp.
///
/// Leap seconds are accepted and clamped to `:59`, as permitted by
/// [RFC 3339 §5.7](https://www.rfc-editor.org/rfc/rfc3339#section-5.7).
pub fn parse_timestamp(s: &str) -> Result<Timestamp, Error> {
    // ...
}
```

rather than reproducing the grammar in the doc comment,
where it will be a subtly wrong copy of the grammar.

## When to Flag

- Crate-level documentation restating `README.md` instead of including it.
- A commit body pasting the doc comment the commit added.
- The same rationale comment appearing in several files (see also W012).
- A doc comment paraphrasing an RFC, wire format, or vendor API where a link and a summary would do.
- A module documenting a fact that each of its functions then documents again.

## When NOT to Flag

- A one-line summary followed by a link. That is a pointer, not a copy.
- An example repeated locally because the reader of that item needs it in front of them.
- A public API doc that is deliberately self-contained because its readers arrive from docs.rs search.
- Two statements that look similar but have different audiences —
  a `# Safety` section and a `// SAFETY:` comment are not duplicates (W006).

## Related Work

Ousterhout states the principle as documenting each design decision exactly once:
if information is already documented outside the program,
do not repeat it inside, just reference it[^1].
C-LINK is the Rust-specific instruction to link rather than restate[^2].
